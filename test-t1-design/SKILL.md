# T1 设计与取样

## 目标

把材料变成可执行契约：每条 AC 有执行方式；verify 类入口有「已取样」接口卡；`cases.json` 只引用卡上字段。

## 输入

接包最小集（生命周期 › 接包最小集）+ `T0-01`（可并行补通识）。不要求开发 SOP 产物。

## 步骤

### 0. 接包与范围

列出本期测 / 不测。写不出可判定期望 → 开口或标待定。建 `artifacts/{需求}-qa/00-当前位置.md`。

### 1. 验收点 → AC

每条 AC：谁在哪做操作、期望观察、执行方式 = `verify` | `手工` | `查库` | `待取样`。能接口验的不标手工。

### 2. 取样（生命周期 › 取样优先级）

对每个 verify 入口按优先级取到可调用；卡上写出处。取不到 → 必问一次问齐；未答复不进 verify。

### 3. 写 T1-04 接口卡 / 页面卡

接口卡：method、相对 BASE 的 path、必需 Header、必需入参、成功/失败观察、出处、取样状态。另附最小成功请求/响应摘录；AC 含反例则至少 1 个失败样例。

页面卡：菜单路径、稳定文案/选择器、期望可见态。

### 4. 切 r1 / r2

r1：探活已通前提下，1 条主路径 + ≤8 冒烟。r2：全量 + 必要回归。主路径须覆盖基址+鉴权+path+主 body。

### 5. 生成 verify 包

`artifacts/{需求}-qa/T1/verify/`：`cases.json` + `run.ps1|sh` + `env.example`。  
**硬约束**：cases 的 path、headers 变量名、body 键必须来自已取样卡；禁止卡外路径。外源 Postman → 导入改写成该单一入口。样例骨架见同目录 `verify/`。

### 6. 必问一次问齐

缺 path/入参/样例/基址变更 → 写入待取样表。未关项对应 AC 不进 cases。

## 规则

- 不编造。无出处不写「已取样」。  
- T0 不全可写卡，但不可计划「T2 宣称接口验收通过」。  
- 纯 UI 只走页面卡 + 手工，不硬塞假接口进 cases。

## 产出

见 [产出模板.md](产出模板.md)：范围与验收、待取样、T1-04、页面卡、verify/。

## 出口

- 每条 AC 有执行方式。  
- 执行方式为 verify 的 AC：接口卡「已取样」，且 cases 引用卡内字段。  
- r1/r2 已切分；必问未关项不阻塞已取样 AC 进入 T2（当前位置写清范围）。  
- 用户确认范围（或「按表执行」）后进 T2。
