# software-test-sop — 专职测试 SOP

状态：**v0.1 骨架**。与 development-sop **互不依赖**；自有接包、取样、verify、缺陷契约。试点（如某真实需求）**另开会话**，本仓只留通用流程。

## 目标

拿到可测材料后，独立完成：弄清环境与鉴权 → 取样锁契约 → 可判定用例 → 按卡执行 → 可复现缺陷。交付满足三条：

1. **可调用**：基址、鉴权、入口（接口或页面）写清，能照做。
2. **可判定**：每条 AC 有期望观察；verify 只跑已取样字段。
3. **可举证**：通过 / 失败出 BUG / 无法证明，均有证据；禁止臆造 path/body。

## 怎么知道地址 / 鉴权 / 路径 / 传参

不靠猜——**两层事实 + 取样优先级**：

| 层 | 放哪 | 放什么 |
|----|------|--------|
| 项目通识 | `T0-01-测试手册` | 基址、鉴权菜谱、信封与成功码、角色矩阵、探活 |
| 本需求契约 | `T1-04-接口卡`（+ 页面卡） | method/path/入参/样例/出处；执行方式为 verify 的须「已取样」 |

取样优先级（高→低，取到可调用为止，卡上写出处）：

1. 接口说明 / Postman / OpenAPI  
2. 前端 API 模块走读  
3. 后端 Controller 走读（有代码读权限时）  
4. 浏览器 / 代理抓包  
5. 手册「参照」同类功能  
6. 仍未知 → **开口必问**；未答复前该 AC **不进 verify**，标「待取样」

**缺事实就停问**：禁止把臆造的 path/body 当验收。T2 只读 T0 + T1-04 + cases；卡与环境不一致 → BUG 或回 T1 改卡，不现场发明参数。

## 阶段

| 阶段 | 做什么 | 出口 |
|------|--------|------|
| T0 | 跨需求通识：基址、鉴权、信封、探活、角色 | 写全；不全禁止宣称该项目接口验收通过 |
| T1 | 范围/AC、取样、接口卡/页面卡、cases | verify 类 AC 卡已取样；cases 与卡一致 |
| T2 | 按卡执行；记结果与证据 | 本轮有结果（通过/失败/无法证明） |
| T3 | 缺陷交接 | 缺陷可复现（BUG 契约齐） |

详： [生命周期.md](./test-overview/生命周期.md)。

## 产物树（项目侧）

```
artifacts/
  _project/T0-01-测试手册.md
  {需求}-qa/
    00-当前位置.md
    T1/   范围验收、接口卡、页面卡、verify/
    T2/   结果-rN、证据
    T3/   BUG 单
```

`verify/` 最小集：`cases.json` + `run.ps1|sh` + `env.example`。账号进 `env.local`（不入库）。样例见 `test-t1-design/verify/`。

## 导入

把 `software-test-sop/test-*` 拷到 `.cursor/skills/` 或 `~/.cursor/skills/`。skill 无项目专有 URL/服务名；示例只用 `{BASE}` / `{svc}`。

## 接包最小集（不要求开发 SOP 产物）

范围与验收点、环境可达、鉴权菜谱、至少一种可调入口、可判定期望。缺任一项 → 停在「有一个问题」或标无法证明。

## 明确不做

- 不依赖、不修改 development-sop。  
- 不在 T2 现场发明 path/body。  
- 不做大型自动化框架生成器。  
- 试点填真实基址/Bearer/接口卡 → **另会话**（本 README 不写死项目名）。

## 适用范围

流程与技术栈无关；命令与路径写入手册与接口卡。外源 Postman 等导入后改写成单一 `verify/` 入口。
