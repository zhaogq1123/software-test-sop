# T3 缺陷交接

## 目标

每条失败变成开发/环境方可独立复现的 `BUG-xx`，字段齐、证据在、阻塞级别清楚。

## 输入

`T2-01-结果-r{N}` 中结果为失败的行 + 证据；对应 AC 与接口卡/页面卡。

## 步骤

1. 一条失败对应一条 `BUG-xx`（可合并同一根因的多 AC，但复现步骤须覆盖）。  
2. 按产出模板填契约字段；复现步骤只使用卡上已有 path/入参与手册鉴权。  
3. 阻塞级别：阻塞发布 / 本需求必须修 / 可后续。  
4. 更新 `00-当前位置` 与 T2 结果表中的 BUG 链接。  
5. 交接：把 BUG 文件（或等价字段）交给修复方；测试侧等回归时开 T2 新轮。

## 规则

- **可复现**：无稳定步骤不出单；偶发写清频率与条件，级别降为可后续或无法稳定复现。  
- **不发明参数**：复现用词来自 T0/T1-04；与卡不符的实际值写在「实际」栏。  
- **不用**开发 SOP 的 A/B/C/D 分类；根因猜测可写「疑似」并与证据分开。  
- 卡/文档错误不是实现 BUG → 回 T1，不建实现缺陷单（可建「文档」类备注，非阻塞实现）。

## 产出

`artifacts/{需求}-qa/T3/BUG-xx.md`（见模板）。可另有 `T3-00-索引.md` 列表。

## 出口

- 每个失败项有 BUG 或已标回炉改卡。  
- BUG 含：AC、复现、实际/期望、证据、阻塞级别、环境与角色。  
- 修复回归 → 新开 T2 轮次，引用 BUG 号验证关闭。
