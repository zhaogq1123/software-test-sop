# T0 测试手册

## 目标

一份 `artifacts/_project/T0-01-测试手册.md`，让任意需求 T1/T2 开工时知道：测哪个基址、怎么登录拿令牌、成功码长什么样、用什么角色、环境是否活着。

不是需求用例集。只记跨需求复用的通识。

## 什么时候做

| 时机 | 做什么 |
|------|--------|
| 首次接触项目 | 按模板建；账号密码只进 `env.local`，手册只写菜谱与变量名 |
| 基址/鉴权/信封变化 | 改手册对应节；注明更新日期 |
| T1/T2 发现手册与真环境不符 | 以真环境为准改手册；相关卡重取样 |
| 新角色/新参照验过 | 补角色矩阵或参照表 |

## 必须写清（见同目录模板）

1. **基址**：`{BASE_URL}` 形态；各环境一行（怎么拼 `{BASE}/{服务短名}/...`）。  
2. **鉴权菜谱**（逐步可照做）：登录页或登录接口 → 响应哪个字段是令牌 → 后续哪个 Header（及固定头如 `appid`）。  
3. **信封**：成功业务码字段名与取值；失败码与文案字段。  
4. **身份**：角色矩阵（权限有/无、审批人等）与申请方式；**密码不进手册**。  
5. **只读探活**：一条「登录 + 打一个已知老接口」命令；与本需求无关的参照接口即可。

## 规则

1. 每条关键事实带来源：文档名、确认人、或探活 `out` 摘录位置。无来源的标「待确认」。  
2. 写「怎么做」，不写「有什么系统」。  
3. 手册与真环境不符 → 改手册；禁止 T2 为迁就错误手册而发明参数。  
4. 不写需求专属 path/AC；那些进 T1-04。  
5. 探活未通 → 手册可存稿，但 **禁止进入 T2 宣称接口验收通过**（见生命周期 › 阶段与出口）。

## 产出

`artifacts/_project/T0-01-测试手册.md`（结构见模板）。

## 出口

- 基址、鉴权菜谱、信封、角色矩阵、探活五节有内容且可照做。  
- 探活在本环境至少成功一次（结果摘录入手册或 T1 附录）。  
- 「你要做的」无待补通识（或明确仅阻塞接口类 T2，UI 手工可并行时在当前位置写清）。
